Findings

Four results from 22 configurations

1

Multiple choice saturates above 3B

16 of 22 configurations exceed 90%. Past 3B, each size step adds only 1 to 3 points. The best models reach 99.2%.

2

Free response keeps scaling

Judge scores rise with size at every cognitive level, from 1.71 to 4.52 overall. Implement-level questions separate models the most, 1.36 to 4.54.

3

The two formats measure different things

Mid-size models (3B to 8B) often pick the right option but struggle to explain the architecture behind it. Multiple-choice accuracy alone overstates what a model can do.

4

Augmentation depends on size

Chain-of-thought (+think) lifts free-response quality by 0.15 to 0.42. Web-search tools (+tool) hurt models below about 8B parameters.

The benchmark

188 questions across five topics and four levels of thinking

CAKE covers microservices, containers, orchestration and managed cloud services. Its levels follow Bloom's revised taxonomy: recall a fact, analyze a situation, design a system, implement it in code. Implement-level knowledge is tested only through free response.

Questions per topic and level

Where the concepts come from

85 core concepts drawn from practitioner references, including:

  • AWS Well-Architected Framework
  • microservices.io
  • Azure Architecture Patterns
  • Kubernetes Enhancement Proposals
How the questions were built
Generate
Claude Opus 4.5 wrote 200 candidates from a template per topic and level, with manual review between batches.
Validate
Four domain experts rated clarity, correctness and difficulty from 1 to 5. 658 annotations in total.
Filter
12 implement-level MCQs were dropped for a formatting defect, leaving 188. CAKE-Core keeps the 116 that every expert rated clearly and correctly, with no flags.
Try a question

Answer what the models answered

Four real questions from CAKE-Core, one per level. Options are shuffled each time, as in the benchmark, where every MCQ is asked three times in a different order.

Scoring

Majority vote for options, an LLM judge for written answers

All models run at temperature 0. Local models run on Ollama; GPT models run through OpenRouter. Provider modules share one interface, so a model can be swapped without touching the evaluation logic.

Input

188 questions

130 multiple choice, 58 free response, each tagged with topic and level.

22 configurations

Three execution modes

base+think+tool

base answers directly. +think adds a reasoning preamble and raises the token limit from 256 to 2048. +tool gives the model web search and browsing.

Multiple choice
Ask 3 times, options shuffled→Majority answer→Accuracy + conviction

Conviction is the share of runs that agree with the majority: ●●● 1.0 or ●●○ 2/3.

Free response
Question + rubric + answer→DeepSeek-R1:32B judge→Score 0 to 5

One deterministic judge, chosen for stable scores across runs.

Answer extraction tries, in order: explicit pattern→strip <think> tags→JSON parse→regex

Limitations

Six limits the paper names

  1. ScopeCAKE targets cloud-native architecture. Results may not carry over to classical patterns.
  2. Distractor qualityExperts found elaboration bias in some wrong options. Shuffling handles position bias, and CAKE-Core filters the weakest items.
  3. Excluded implement MCQs12 implement-level MCQs were dropped for a formatting defect, leaving 130 MCQs.
  4. One judgeFree response relies on DeepSeek-R1:32B, partly cross-checked with Gemini 2.5 Pro.
  5. Inter-rater reliabilityα near zero is a known artifact of skewed ratings. Future rounds should use wider scales.
  6. Longest option winsThe correct option is often the longest one, which a model could exploit. Future rounds should control distractor length.

Future work adds correctly formatted implement-level MCQs, classical architecture patterns, a study of augmentation strategies by model size, and multilingual versions.
